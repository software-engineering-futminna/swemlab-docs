# 01. Pedagogical Framework & Academic Curriculum

**Course:** FUTM-SWE-221: Individual Software Development Project I  
**Semester:** Second Semester  
**Department:** Department of Software Engineering, FUTMinna  

---

## 1. Pedagogical Vision
SWE-MLAB was engineered to bridge academic classroom theory and commercial software engineering practice. Rather than submitting static code zip files, students develop and deploy cloud-native applications across structured agile sprints.

---

## 2. 4-Sprint Lifecycle

| Sprint | Timeline | Objectives & Learning Outcomes |
|---|---|---|
| **Sprint 1** | Weeks 1–3 | **Architecture & Wireframing:** Problem formulation, public REST API evaluation, component tree planning, and role allocation. |
| **Sprint 2** | Weeks 4–7 | **Async API Integration:** Asynchronous JavaScript (`fetch`, `async/await`), JSON schema validation, error boundaries, and rate limit resilience. |
| **Sprint 3** | Weeks 8–10 | **Client-Side Resilience & UX:** Offline storage (`localStorage`/Service Workers), PWA manifests, Swiss typography, and accessibility contrast. |
| **Sprint 4** | Weeks 11–13 | **Cloud Deployment & Defense:** Continuous delivery on Netlify/Vercel/Railway, semantic commit review, and oral defense. |

---

## 3. Evaluation Rubrics

Submissions are scored on a standardized 100-point rubric:
- **Core Functionality & Business Logic (40%):** Feature completeness, dynamic state management, filtering, and responsive interactivity.
- **API Integration & Resilience (20%):** Robust asynchronous fetching, error fallback states, and defensive JSON schema parsing.
- **UI/UX & Swiss Design Standards (20%):** Strict grid alignment, typographic contrast, mobile touch responsiveness, and zero visual clutter.
- **Git Hygiene & Collaboration (20%):** Commit distribution among team members, meaningful pull requests, and repository README documentation.

---

## 4. Student Developmental Context
These submissions represent foundational 200-level undergraduate coursework. They demonstrate practical mastery of core web and API principles rather than hardened commercial platforms.
