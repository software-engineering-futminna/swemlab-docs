Section 01 — Institutional Authentication

Automatic Domain-Based Onboarding

When a user signs in with GitHub, SWE-MLAB inspects all verified email addresses linked to their GitHub profile (primary or secondary) and automatically assigns their institutional role.

1. Departmental Super Admin (role = "super_admin")

Assigned automatically to the departmental GitHub account (software-engineering-futminna) or any GitHub account with a verified softwareng@futminna.edu.ng address.

  • Views and manages all courses across all lecturers in the department
  • Full access to all course leaderboards and Senate CSV grade exports
  • Custodian of the software-engineering-futminna GitHub Organization

2. Academic Staff & Instructors (role = "instructor")

Assigned automatically to any lecturer or staff member who has a verified @futminna.edu.ng email (excluding @st.futminna.edu.ng) attached to their GitHub account. Staff may keep their personal email as primary on GitHub—SWE-MLAB detects verified secondary university emails automatically.

  • Immediate access to the 7-tab Instructor Panel at /instructor
  • Creates and manages courses, weekly coding activities, and project topics
  • Uploads PDF/DOCX lecture notes for the student RAG AI Tutor
  • Launches and migrates student team repositories into the Department GitHub Organization

3. Undergraduate Students (role = "student")

Assigned automatically to students with a verified @st.futminna.edu.ng email on GitHub. Accounts without a verified FUTMinna email are declined with /?error=institutional_email_required.

  • Enrolls in courses and launches GitHub Codespaces ("Open Forge")
  • Forms project teams, invites classmates, and queries the AI Course Tutor

Section 03 — Training Curriculum

6-Module Onboarding Workshop Schedule

Structured full-day onboarding schedule for Departmental Leadership, Academic Instructors, and Laboratory Technologists.

Architecture & Governance Overview

  • 1System Stack: Go 1.22 (Gin + GORM) API, React 18 SPA, Neon Serverless PostgreSQL database, and GitHub REST API v60 integration.
  • 2Domain Role Mapping: softwareng@futminna.edu.ng / software-engineering-futminna maps to Super Admin; *@futminna.edu.ng maps to Instructor; *@st.futminna.edu.ng maps to Student.
  • 3Live Academic Showcase: Review the 20 student teams and deployed projects at software-engineering-futminna.github.io/showcase.

Hands-On Staff Onboarding Exercise

  • AEach lecturer opens github.com/settings/emails and adds their official @futminna.edu.ng email address.
  • BVerify the confirmation email sent by GitHub inside FUTMinna staff webmail.
  • CSign in to SWE-MLAB with GitHub and confirm immediate access to the Instructor Panel (/instructor).

Course & Weekly Activity Creation

  • 1Create Course (Tab 1): Enter Title, Course Code, and Semester. Add at least one activity immediately so the empty-course safeguard is not triggered.
  • 2AI Activity Generator (Tab 2): Click AI Generate, provide Topic, Learning Objectives, Programming Language, and optional Lecture Excerpt, then apply the generated specification to the form.
  • 3Plan Semester Bulk Tool: Use Plan Semester to generate 12 weekly slots in one operation.

Publishing & Student Cloud IDE ("Open Forge")

  • ADraft vs. Live Status: New activities default to Draft (hidden from students). Toggle to Live when ready for class.
  • BGitHub Codespaces Provisioning: Starting an activity automatically creates the student's repository with .devcontainer/devcontainer.json and .github/workflows/autograde.yml.

Uploading & Indexing Course Material (Tab 5)

  • 1PDF & DOCX Upload (Max 20 MB): Upload weekly lecture handouts in Tab 5 (Lecture Notes).
  • 2Background Text Extraction: Backend validates file headers (%PDF or PK\x03\x04), extracts text asynchronously, and stores indexed LectureChunk records in PostgreSQL.

Verifying the Student AI Tutor

  • AConfirm the note status transitions from Processing to Ready and the chunk counter increments.
  • BTest the Student AI Tutor on /dashboard to verify that answers cite the uploaded lecture notes.

Project Specification & Team Formation (Tab 6)

  • 1Create Project Topic: Define project requirements manually or via the AI Project Generator, and set maximum team size (2–6 students).
  • 2Student Team Rosters: Team Leads create teams and invite classmates by GitHub username or Matric Number.

Launch Repo vs. Migrate to Org

  • ALaunch Repo (/teams/:id/launch-repo): Creates a new repository directly inside software-engineering-futminna.
  • BMigrate to Org (/teams/:id/migrate-repo): Transfers an existing personal student repository into software-engineering-futminna, sets it to Public, and re-invites all team members as collaborators.

Three-Mode Assessment & Moderation

  • 1Automated & AI Grading (Tab 3): Combine GitHub Actions webhook autograding (100% pass / 50% partial) with Gemini AI qualitative feedback and manual instructor scoring.
  • 2Results Moderation (Tab 7): Toggle Hide Results from Students during grading moderation and use + Add Result to enter or override scores by GitHub username.

Senate CSV Export & Public Showcase

  • AExport CSV (Tab 4): Download ranked course results with Matric Numbers for departmental examination records.
  • BShowcase Publication: Add top student projects to software-engineering-futminna.github.io/showcase for accreditation visibility.

Super Admin Verification

  • 1Sign in using the departmental GitHub account (software-engineering-futminna / softwareng@futminna.edu.ng).
  • 2Verify global visibility across all departmental courses, activities, teams, and leaderboards.

Infrastructure Handover & Sign-Off

  • AConfirm access to Neon PostgreSQL (DATABASE_URL), GitHub OAuth credentials, GEMINI_API_KEY, and Sentry alerts.
  • BComplete and print the Handover Verification Checklist in Section 6.

Section 05 — Technical Custodian Reference

SQL & Git Maintenance Runbook

Standard SQL queries and Git commands for routine departmental maintenance and edge-case recovery.

1. Departmental Super Admin Database Sync

Ensures softwareng@futminna.edu.ng and GitHub account software-engineering-futminna hold super_admin privileges: 

UPDATE users
SET role = 'super_admin',
    institutional_verified = true
WHERE LOWER(email) = 'softwareng@futminna.edu.ng'
   OR LOWER(username) = 'software-engineering-futminna';

2. Update Staff Who Logged In Before Email Verification

If a lecturer signed in before verifying their @futminna.edu.ng email on GitHub, run this query once: 

UPDATE users
SET role = 'instructor',
    institutional_verified = true
WHERE LOWER(email) LIKE '%@futminna.edu.ng'
  AND LOWER(email) NOT LIKE '%@st.futminna.edu.ng'
  AND role != 'super_admin';

3. Reset Stale Repository Migration URL

If a team repository URL points to a deleted placeholder in the organization, reset it to the student's personal repo before clicking Migrate to Org: 

UPDATE teams
SET repo_url = 'https://github.com/StudentOwner/repo-name',
    repo_full_name = 'StudentOwner/repo-name'
WHERE id = <team_id>;

4. Sync Personal Repository into Empty Org Repo

If a team pushed their commits to a personal repo while their organization repo remained empty: 

git clone https://github.com/StudentUsername/PERSONAL-REPO.git temp_sync
cd temp_sync
git remote set-url origin https://github.com/software-engineering-futminna/ORG-REPO.git
git push origin main --force
cd .. && rm -rf temp_sync
